- **Review date:** 2026-08-13 (Europe/Moscow)
- **Review point:** complete intended source before the provisional package checkpoint
- **Artifact state during review:** no RC7 package byte set, image, or production signature existed
- **Normative inputs:** fetched `origin/main` Phase 0 decision/scope/evidence, then the exact PR #20 reference sequence recorded in the Phase 1 source record

## Blocking findings and dispositions

1. **Resolved — stale merge-result collateral exceeded the RC7 boundary.** The
   exact historical merge replay also removed the current main relay routing
   script and registry design, truncated current owner/footer documentation,
   and replaced the main README wholesale. Those changes were unrelated to the
   0.7.11 trust/update bridge or adopted-overlay repair. The files were restored
   byte-for-byte from the verified `origin/main`; README now has only a narrow
   RC7 draft-guidance correction.
2. **Resolved — pull-request CI initially named the synthetic merge SHA.** A
   pull-request `github.sha` can be the test merge commit rather than the
   reviewable branch head. Ordinary CI now passes
   `github.event.pull_request.head.sha || github.sha` into the reusable
   preflight, which checks out and compares that exact SHA. Candidate and
   release workflows compare the returned verified SHA before any artifact job
   becomes eligible.
3. **Resolved — active RC6 candidate identifiers survived the first mechanical
   audit.** Active workflow/test filenames, fixture domains, expected path
   labels, current VM methodology, candidate templates, and current comments
   were moved to RC7. RC6 remains only where it identifies an immutable
   historical input, version-order transition, or the Phase 0/Phase 1
   provenance record. The `68976508...` signed-manifest digest remains `null`
   and explicitly unknown.
4. **Resolved — release collateral was tied to workstation and historical
   bytes.** The tracked replacement reads release identity, package facts, and
   storage rules from validated inputs, contains no absolute workstation path,
   embedded source/package hash, embedded package size, or fixed storage
   threshold, and refuses canonical output without matching signature proof.
5. **Resolved — the focused updater test runtime initially installed ucode but
   not the pinned public-signature verifier.** The preflight now installs the
   repository-pinned `usign` test tool as well as ucode. It receives no private
   key, secret, protected environment, or signing job permission.
6. **Resolved — local Python bytecode compilation initially targeted a
   workstation cache outside the isolated worktree sandbox.** The preflight
   now uses a disposable `PYTHONPYCACHEPREFIX` and removes it on exit; no
   generated bytecode enters the source tree or user cache.

No blocking review finding remains before the exact-SHA CI gate.
