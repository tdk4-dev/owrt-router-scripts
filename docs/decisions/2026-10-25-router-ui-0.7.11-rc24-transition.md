# RC24: permit the installed RC22 protocol-2 source

Owner direction on 2026-10-25 is to complete the first 0.8 roadmap prerequisite:
the package-only 0.7.11 bridge, including its RC22 update path, Tailscale,
reboot, rollback and eventual checked stable packages. A spare Xiaomi will be
identified separately before physical testing. No existing customer router is
implicitly selected by this instruction.

## Defect and scope

The immutable signed RC23 manifest omitted source `0.7.11-rc.22` protocol 2.
Its physical canary therefore refused before mutation. Both the producer and
validator used the same outdated source list, allowing source tests to pass.

RC24 is `0.7.11-rc.24` / `0.7.11~rc24-1` / candidate. Its branch starts from
fetched main `18562f49bcac914acf3b07749f5b8863d8016e00` and preserves RC23
`b49cd98d3d70b2a2b7ba3271420840d4ffe644a5` through an ordinary merge.
RC22 and RC23 source/artifacts remain unchanged.

The only new accepted transition is RC22 with protocol 2. Candidate and future
stable staging must include it, and their validators must reject its omission.
Protocol 1/unknown protocols do not gain permission. Existing supported sources
and RC7/RC18 refusals remain intact. Router runtime, UI, ACLs, routing, package
installation and RC23's Tailscale lifecycle implementation are unchanged.

## Acceptance and evidence boundaries

- Retain the failing regression against unchanged RC23, then test generated
  candidate/stable manifests through the actual runtime authorization helper.
- Test missing/wrong-protocol RC22 entries and preserve historical refusals.
- Pass fresh exact-source preflight and CI before canonical signing/builds.
- Compare independent clean package/feed builds and verify production signing.
- On exact new bytes, test RC22 update, reboot/commit, rollback, reapply and
  Tailscale identity/running intent/peer return routing in a disposable VM.
- Identify the owner spare and verify recovery access before the physical gate.
- Stable identity is a separate byte set requiring its own final evidence;
  publication requires main containment and the completed hardware gate.

Risk is release-critical manifest authorization. No previous RC's evidence
qualifies the new artifact tuple. Firmware images, Factory and 0.8 feature work
remain outside this package-only bridge change. No hardware result or public
release is claimed by this decision.
