## Reproduced failure

Exact RC20 rescue SHA-256
`d3ecb2efb8bef7b331ec5e3e0f087fbfe464a6b72d7573661ca49be959d5ed68`
reproduced exit 36 on the disposable VM after rollback and an explicit reboot.
The transaction restored `0.7.10` successfully. Its original failed attempt and
subsequent independent reproduction remain retained under their original identities.

Rollback correctly restored the old opkg registration database. `nohup` remained
available, but the `ip-full` and `conntrack` dependencies were no longer registered.
Reboot removed volatile feed indexes. The rescue prerequisite function returned
as soon as it found `nohup`, bypassing the only feed update. Project installation
therefore started without resolvable dependency metadata and rolled back.

## Narrow correction and acceptance

Every rescue attempt prepares dependencies before the optional `nohup` repair.
On the first attempt, download only the explicitly configured HTTPS OpenWrt
indexes, verify their signatures against the router's trusted OpenWrt keys, and
retain their exact bytes and hashes outside transaction rollback state. Bind
the cache to the exact target manifest, OpenWrt release, feed configuration and
public trust inputs. Subsequent reapply verifies this same contract; it never
refreshes a pin from a changed server or substitutes another public feed.

Use an isolated opkg configuration and retained lists for both prerequisite and
project installation. A download-only resolution of `coreutils-nohup`, `ip-full`
and `conntrack` must succeed before any package installation. opkg retains its
package hash verification; index signatures are checked explicitly on every use.
Missing, changed, corrupt, untrusted or unavailable inputs refuse installation.
The persistent feed cache is recovery material, not a fourth project IPK.

Acceptance requires focused source tests and a real disposable-VM checkpoint
covering initial install, exact rollback, reboot, retained `nohup`, reapply,
dependency availability and pre-mutation failures. The complete release matrix
and all 46 applicable browser controls must then pass on new canonical bytes.

signatures and partial VM/browser results do not qualify RC21. RC21 requires
fresh exact-source Tier 0/CI, clean independent builds with byte equality,
protected production signing and a new frozen artifact set. No RC20 artifact

unsupported RC18 pre-mutation refusal, and later stable requalification remain

canary using its exact frozen stable bytes. This task authorizes no hardware
